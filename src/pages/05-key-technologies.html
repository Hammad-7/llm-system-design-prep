LLM System Design · Fast Track

Key Technologies

The tools that show up in LLM system design answers: model providers and serving engines, vector stores, gateways, orchestration, evaluation and guardrails. What each one is for, and the one sentence to say about it.

Interviewers don't expect you to know every product, and they care far more about why you'd use a category than which logo you pick. Still, naming a concrete, well-known technology makes your design feel real and opens the door to deeper questions you can answer. Learn one or two options per category well, plus the trade-off that separates them.

The classic building blocks don't go away. Conversation history lives in a database, traces flow through a queue, and session state sits in a cache. If you need refreshers, Hello Interview's key technology pages on Redis, Kafka, PostgreSQL and Temporal pair well with this page.

Model providers (hosted APIs)

Frontier model APIs

Anthropic ClaudeOpenAIGoogle Geminivia AWS Bedrock / Google Vertex / Azure

Use whenAlmost always as your default. Best quality, zero GPU operations, pay per token. Know aboutStreaming, tool use, structured outputs, prompt caching, batch APIs (commonly 50% off for async work), tiered rate limits (tokens per minute), regional data residency, zero-data-retention options. Say"I'll start with a hosted model behind our own gateway so we can switch providers or add a self-hosted tier later without touching application code."

Open-weight models

LlamaQwenMistralDeepSeekGemma

Use whenData can't leave your infrastructure, you need fine-tuning control, or volume is high enough that GPUs you keep busy are cheaper than per-token pricing. Trade-offYou now own capacity planning, autoscaling, upgrades and on-call. Idle GPUs are expensive; self-hosting wins only at sustained high utilization or with strict privacy needs.

Inference serving

Serving engines

vLLMSGLangTensorRT-LLM

What they doTurn model weights into a high-throughput, OpenAI-compatible endpoint: continuous batching, paged KV cache, prefix caching, quantization, speculative decoding, multi-GPU parallelism, multi-LoRA serving. DifferencesvLLM (PagedAttention) is the broadest default. SGLang centers its scheduler on prefix reuse (RadixAttention) and does well on multi-turn and shared-prefix workloads. TensorRT-LLM is NVIDIA's compiled, highly tuned option. Say"Each replica runs vLLM with continuous batching and prefix caching; the router is what makes the fleet efficient."

Cluster orchestration for inference

llm-dNVIDIA DynamoKServeRay ServeKubernetes + GPU autoscaling

What they addFleet-level concerns the engine doesn't handle: cache-aware and load-aware request routing, prefill/decode disaggregation across pools, model rollout, autoscaling on queue depth or KV utilization. llm-d, a CNCF sandbox project, scores replicas on prefix-cache locality and load instead of round-robin. Say"Round-robin wastes prefix caches. I'd route by conversation or prefix hash with a load-aware fallback."

Retrieval

Vector databases and search engines

pgvectorPineconeQdrantWeaviateMilvusElasticsearch / OpenSearchVespaturbopuffer

Choose byScale (millions vs billions of vectors), need for hybrid keyword + vector search, filtering and multi-tenancy model, operational appetite (managed vs self-run), and whether you already run Postgres or Elasticsearch. Defaultspgvector when data is already in Postgres and the corpus is up to tens of millions of chunks: transactions, joins and ACLs come for free. A dedicated vector DB (Pinecone, Qdrant, Weaviate, Milvus) for larger scale, many tenants or heavy filtering. Elasticsearch/OpenSearch or Vespa when keyword search and ranking matter as much as vectors. Say"I'll use one engine that does BM25 and vectors together so hybrid search is a single query with ACL filters applied inside the search."

Embedding and reranking models

OpenAI embeddingsCohere Embed & RerankVoyageBGE / open modelscross-encoders

KnowEmbedding dimension drives storage and search cost. Changing embedding models means re-embedding the whole corpus, so version embeddings and plan migrations as dual-write plus backfill. Rerankers are slower per document but far more accurate; run them on the top 50–100 candidates only.

Document parsing and ingestion

UnstructuredDoclingApache TikaOCR / vision modelsKafka, Debezium (CDC)

Why it mattersGarbage in, garbage retrieved. PDFs, tables and slides need layout-aware parsing; scanned documents need OCR or a vision model. Ingestion is a pipeline (fetch → parse → chunk → enrich → embed → upsert) run by workers off a queue, triggered by change events.

Gateways and orchestration

LLM gateways

LiteLLMPortkeyEnvoy AI GatewayKong AI GatewayCloudflare AI Gateway

What it doesA single internal API in front of every model: provider keys, routing and fallback, per-tenant token quotas and budgets, caching, PII redaction, logging and cost attribution. Say"Every model call goes through the gateway, which gives us one place for quotas, fallbacks and cost tracking. Uber built exactly this kind of GenAI gateway to serve dozens of internal use cases."

Agent and LLM application frameworks

LangGraphLlamaIndexOpenAI Agents SDKClaude Agent SDKPydantic AI

Use whenYou want a graph or loop abstraction for multi-step LLM workflows, built-in tool calling, state and streaming. Many teams use plain code plus the provider SDK; frameworks are optional. Interview tipDon't make the framework the architecture. Draw the orchestrator as a service with clear responsibilities; mention the framework as an implementation detail.

Durable execution and queues

TemporalAWS Step FunctionsKafkaSQSRedis Streams

Use whenAgent runs or document pipelines take minutes to hours, span many LLM and tool calls, and must survive crashes, retries and human approval pauses. Durable workflows checkpoint each step so a failure resumes instead of restarting. Say"Each agent run is a durable workflow; each LLM call and tool call is an activity with its own timeout and retry policy, and approvals are signals."

Protocols

Model Context Protocol (MCP)Agent2Agent (A2A)OpenAI-compatible APIs

KnowMCP standardizes how models discover and call tools and data sources; its 2026-07-28 spec made the core stateless and standardized OAuth-based authorization for remote servers. A2A covers agent-to-agent communication. The OpenAI-compatible HTTP API is the de facto interface most serving engines and gateways expose.

Evaluation and observability

Tracing, evals and prompt management

LangfuseLangSmithArize PhoenixBraintrustRagaspromptfooOpenTelemetry GenAI conventions

What they doCapture each request as a trace (prompt version, retrieved chunks, tool calls, tokens, latency, cost), run offline eval suites with LLM judges, compare prompt and model versions, and collect user feedback. Langfuse and Phoenix are open source; LangSmith and Braintrust are managed. Say"Every trace is tagged with prompt and model version, so we can slice quality and cost by release and replay failures into the eval set."

Safety and security

Guardrails

Llama GuardNeMo GuardrailsMicrosoft Presidio (PII)provider moderation APIsschema validators

Use forInput and output classification (toxicity, self-harm, policy), PII detection and redaction, jailbreak and injection heuristics, topical rails. Run cheap classifiers in parallel with the main call to avoid adding latency. RememberClassifiers reduce risk; architecture (least privilege, confirmation, isolation) contains it.

Sandboxes for code and tools

Firecracker microVMsgVisorE2Bcontainers with no network egress

Use whenThe model writes and runs code, browses, or touches files. Each run gets an isolated, short-lived environment with CPU/memory/time limits, no secrets, and an egress allowlist.
